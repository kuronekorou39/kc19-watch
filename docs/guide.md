# 詳細ガイド

README に載せていない詳しい説明をまとめています。

## 設定ファイルの役割

| ファイル | 形式 | 役割 |
|---|---|---|
| `settings.share.yaml` | YAML（コメント可） | 配る人が実値を書いて**別途共有**する。サイトURL・施設ID・プラン・通知対象など。gitignore 済み |
| `settings.share.example.yaml` | YAML | ↑のひな形（リポジトリに含まれる。実値なし） |
| `settings.local.json` | JSON | アプリが自動で読み書きする保存先。トークン・個人情報もここ。**手で編集しない**。gitignore 済み |

`settings.share.yaml` を exe（またはプロジェクト）と同じフォルダに置くと起動時に自動で
取り込まれます。画面の「設定」タブ →「📄 設定ファイルを読み込む」でも取り込めます。
ファイルの更新日時を覚えているので、画面で直した値が起動のたびに戻ることはありません。
また、共有ファイルの空欄項目は「指定なし」扱いになり、画面で設定済みの値を消しません。

## Web ダッシュボード（http://127.0.0.1:8000）

- **走査タブ**：空室状況（部屋 × プラン × 日付・予約リンク）、推移グラフ、変化履歴、
  稼働ログ、開始/停止・間隔変更・手動チェック。通知対象の部屋（🔔）が先頭に表示される
- **設定タブ**：
  - 「必須」…共有ファイル読み込み + チェックリスト。必須が揃うまで走査開始はロック
  - 「テレグラム通知」…トークン入力 → 再起動なしで接続・テスト通知。
    **通知する部屋**をチェックボックスで選択（チェックなし＝全部屋を通知。変更は即保存）
  - 「任意」…予約アシスト・代表者情報
- 初回起動時は設定タブが開く
- 解禁バースト：指定時間帯だけ間隔を狭め、時間外は自動で通常間隔に戻る

## Telegram コマンド

- `/start` 監視開始＆通知先登録 ／ `/end` 停止 ／ `/now` 現在の状況 ／ `/info` 情報 ／ `/help`
- 個人チャットで `/start` した人は誰でも通知先に登録され、監視を開始/停止できます。
  Bot のユーザー名はむやみに公開しないでください

## 予約アシスト（handoff・任意）

- 空室検知時、ブラウザ（PCの Chrome/Edge）で予約フォームを自動入力し
  「確認画面」まで進めて残す
- **最終確定（予約するボタン）は人間が押す**設計。Bot は確定しない
- 各項目は独立入力（フォームが多少違っても壊れず、埋められた分だけ入れて報告）
- 対象部屋を指定しない場合は「通知する部屋」と同じ範囲で動く

## 監視の仕組み

- 予約サイトの在庫APIを定期ポーリングし、部屋×プラン×日付ごとに空室数を取得
- **走査は応答に含まれる全部屋が対象**（部屋名も自動取得）。プランごとに返る部屋は
  異なるため、プランを全部列挙すると施設全体をカバーできる。
  `scan_room_ids` を指定した場合だけ走査を限定できる
- 前回との差分（満室→空室、空室→満室）を検知して Telegram 通知。初回はベースライン記録のみ。
  **通知は「通知する部屋」で選んだ部屋だけに絞れる**（未選択＝全部屋を通知）。
  履歴・推移グラフには通知対象外も含む全部屋のデータが残るので、
  どの部屋がいつ空いていつ埋まったかを後から確認できる
- 状態・履歴は SQLite（`*.db`、gitignore）に永続化。ログは `logs/`（gitignore）
- 1周期のリクエスト数はプラン数×検索人数（例: 6プラン×4人数=24回）。
  プランを増やしたら間隔を長めにしてアクセス頻度を保つ

## 配布の詳細（配る側）

```powershell
./build_exe.ps1   # => dist/kc19-watch.zip（exe + README.txt 入り）
```

1. Releases には `kc19-watch.zip` **だけ** を上げる
2. `settings.share.example.yaml` をコピーして実値を埋め、`settings.share.yaml` として
   LINE 等で**別途**共有する（リポジトリ・Releases には絶対に含めない）
